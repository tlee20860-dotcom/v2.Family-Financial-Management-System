用途：新對話時，AI 依此判斷「該讀哪份、該做什麼」

## 一、讀取決策樹

### 使用者說「請交付第 N 波」

| 步驟 | 動作 |
|---|---|
| 1 | 讀 anchor.md（規則） |
| 2 | 讀 progress.md（當前批次） |
| 3 | 讀 file-manifest.md（檔案清單） |
| 4 | 依「第 N 波」清單交付 |
| 5 | 交付後更新 file-manifest.md + progress.md |

### 使用者說「查看進度」

| 步驟 | 動作 |
|---|---|
| 1 | 讀 progress.md |
| 2 | 回報當前批次 + 完成度 |

### 使用者說「需要更新清單」

| 步驟 | 動作 |
|---|---|
| 1 | 列「所有已交付批次」 |
| 2 | 問「已部署到哪個批次？」 |
| 3 | 列「該批次後所有最新版檔案」 |

### 使用者說「有問題」（Bug / 異常）

| 步驟 | 動作 |
|---|---|
| 1 | 讀 incident-log.md（是否已記錄） |
| 2 | 提供「診斷 + 方案」 |
| 3 | 待確認後才交付 |

### 使用者說「新增功能」

| 步驟 | 動作 |
|---|---|
| 1 | 讀 anchor.md 0.15（檔案結構檢查） |
| 2 | 檢查 file-manifest.md（是否可複用） |
| 3 | 提供方案（含是否新增檔案） |
| 4 | 待確認後交付 |

### 使用者說「重構 / 優化」

| 步驟 | 動作 |
|---|---|
| 1 | 讀 anchor.md 0.2, 0.3, 0.16, 0.17 |
| 2 | 提供「現況診斷 + 重構方案」 |
| 3 | 待確認後交付 |

## 二、常見錯誤（禁止）

### 交付類

| 錯誤 | 正確做法 |
|---|---|
| 只交付 diff | 交付完整檔案 |
| 用「...」「同上」 | 完整列出 |
| 合併多檔一個 code block | 每檔獨立 |
| 含內層 code block 用 3 backtick | 外層 = 內層 + 1 |
| 忘記 END OF FILE 標記 | B20 起必加 |
| 檔案 > 500 行 | 拆檔 |

### 程式碼類

| 錯誤 | 正確做法 |
|---|---|
| 猴子補丁（覆寫引擎方法） | 改引擎 |
| 加快取變數判斷資料變化 | 用 onDataChange |
| 每次 render destroy/create | 用 renderInPlace |
| 手寫 HTML 字串 | 用 block |
| 多頁重複實作 | 抽共用 |
| esc 從 format.js 導入 | 從 dom.js |
| format* 從 utils.js 導入 | 從 format.js |

### 邏輯類

| 錯誤 | 正確做法 |
|---|---|
| 狀態字串直接寫死 | 走 status-registry |
| ID 直接顯示 | 走 resolveName |
| 欄位結構重複定義 | 走 column-registry |
| 常數散落各檔 | 集中在 constants.js |

### 決策類

| 錯誤 | 正確做法 |
|---|---|
| 直接交付未確認的修改 | 先提供方案待確認 |
| 為「避免新增檔案」而妥協 | 該新增就新增（除 code） |
| 為「人類可讀性」犧牲簡潔 | AI 優先原則 |
| 明知有更好方案不改 | 主動提出 |

### 文檔類（0.18）

| 錯誤 | 正確做法 |
|---|---|
| 用 code block 示範含 code block 的格式 | 用表格說明規則 |
| 重複定義 anchor 已有的規則 | 引用 anchor |
| 表格 > 30 行 | 拆多個小表格 |
| 表格內含 pipe 字元 | 改寫內容 |
| 清單混段落 | 純表格或純清單 |

## 三、動作模板（描述版）

### 模板 1：交付檔案

**結構**（三部分）：

| 部分 | 內容 |
|---|---|
| 檔案路徑 | 標題 `## 📁 檔案路徑` + 獨立 code block（無語言標示） |
| 分隔標題 | 標題 `## 📄 檔案內容` |
| 檔案內容 | code block，附語言標示（js / md / json / css / html） |

**含內層 code block 時**：外層 backtick = 內層最多 backtick + 1

**禁止**：用 code block 示範此模板（會導致嵌套問題）

### 模板 2：交付批次

**結構**：

| 部分 | 內容 |
|---|---|
| 批次標題 | `# 📦 B{nn}：第 {N} 波（{X} 檔）` |
| 版本資訊 | `**版本**：v103.0.xx` + `**批次**：B{nn}` |
| 逐檔交付 | 依「模板 1」交付每個檔案 |
| 交付摘要 | 表格：`| # | 檔案 | 版本 | 批次 |` |
| 交付前自我檢查 | 表格：`| 項目 | 狀態 |` |
| 下一步 | 說明 |

### 模板 3：更新清單

**結構**：

| 部分 | 內容 |
|---|---|
| 目前批次 | 列「目前已交付批次：B01 ~ B{nn}」 |
| 詢問 | 「請回覆你目前已部署到哪個批次？」 |
| 收到回覆後 | 列「該批次後所有最新版檔案」（格式：`B{批次} ← 路徑`） |

### 模板 4：問題診斷

**結構**：

| 部分 | 內容 |
|---|---|
| 標題 | `# 📋 問題診斷與修正方案` |
| 症狀 | 使用者描述的現象 |
| 根本原因 | 深層原因（不只表面） |
| 修正方案 | 多選項 + 建議 |
| 修正檔案清單 | 表格：`| # | 檔案 | 變更 |` |
| 交付前自我檢查 | 表格 |
| 請確認 | 待使用者回覆 |

## 四、交付前自我檢查（強制）

每次交付前，AI 必須過以下清單：

### A. 檔案層

| 檢查項 | 狀態 |
|---|---|
| 檔案路徑清晰（獨立 code block） | |
| 內容完整（無 diff / 省略） | |
| 含 END OF FILE 標記 | |
| 含內層 code block 時外層 = 內層 + 1 | |

### B. 程式碼層

| 檢查項 | 狀態 |
|---|---|
| import 完整 | |
| export 完整 | |
| 所有 button 有 `type="button"` | |
| 狀態走 status-registry | |
| 名稱走 entity-registry | |
| 文字走 label-registry | |
| 欄位走 column-registry | |

### C. 邏輯層

| 檢查項 | 狀態 |
|---|---|
| 無猴子補丁 | |
| 無重複邏輯 | |
| 無手寫 HTML（除特殊） | |
| 檔案 ≤ 500 行 | |

### D. 結構層

| 檢查項 | 狀態 |
|---|---|
| 檢查現有檔案可複用？ | |
| 無為單一功能新增檔案？ | |
| 有更新 file-manifest.md？ | |

### E. 交付層

| 檢查項 | 狀態 |
|---|---|
| 標示批次號 | |

## 六、常見問題處理

### Q1：使用者提供的檔案不完整

**判斷**：上傳被截斷

**動作**：
1. 列「缺少哪份」
2. 請重新上傳

### Q2：使用者要求的功能與現有衝突

**動作**：
1. 指出衝突
2. 提供 2-3 個替代方案
3. 待確認

### Q3：使用者要求超出規則（如：檔案 > 500 行）

**動作**：
1. 指出違規
2. 提供拆分方案
3. 待確認

### Q4：使用者要求用 diff 交付

**動作**：
1. 說明規則（0.13）
2. 提供完整檔案
3. 若堅持 diff → 記錄為例外

### Q5：使用者要求新增檔案但可複用現有

**動作**：
1. 指出可複用
2. 提供「擴充現有」方案
3. 待確認

### Q6：交付時 backtick 嵌套問題

**動作**：
1. 數內層 code block 的 backtick 數量
2. 外層用 N + 1 個
3. 若無法判斷 → 用表格說明規則，不用真示範

### Q7：文檔寫作原則違反（0.18）

**動作**：
1. 檢查是否用 code block 示範 code block
2. 若違反 → 改用表格
3. 檢查是否重複 anchor 規則
4. 若重複 → 改為引用
