## 二、檔案路徑格式範例

**每個檔案交付的「檔案路徑」部分**：

| 情況 | 寫法 |
|---|---|
| 一般檔案 | 用標題 `## 📁 檔案路徑` + 一個 code block 包住路徑 |
| 路徑含特殊字元 | 同上 |
| 多檔交付 | 每檔各自一個路徑區塊 |

**路徑區塊特性**：
- code block 無語言標示（純文字）
- 只放路徑，不放說明
- 路徑相對專案根目錄（不帶 `./`）

## 四、END OF FILE 標記範例

### JS / CSS 檔

| 元素 | 內容 |
|---|---|
| 註解開始 | `/*` |
| 分隔線 | `═══` 重複 |
| 標題 | `END OF FILE` |
| File | `File: {相對路徑}` |
| Version | `Version: v103.0.xx` |
| Batch | `Batch: B{nn}` |
| 註解結束 | `*/` |

### MD 檔

| 元素 | 內容 |
|---|---|
| 同 JS 檔 | 用 `/* ... */` 或 `<!-- ... -->` |
| 建議 | 用 `/* ... */` 保持一致 |

### HTML 檔

| 元素 | 內容 |
|---|---|
| 註解開始 | `<!--` |
| 同 JS 檔內容 | |
| 註解結束 | `-->` |
| 位置 | `</html>` 之後 |

### JSON 檔

| 情況 | 處理 |
|---|---|
| 標準 JSON | ❌ 不支援註解，不用標記 |
| 若需追蹤版本 | 加 `"_meta": {...}` 欄位 |

## 五、更新清單操作範例

### 情境：使用者說「需要更新清單」

**AI 回應格式**：

| 元素 | 內容 |
|---|---|
| 標題 | 目前已交付批次 |
| 列表 | B01 ~ B{nn} |
| 詢問 | 請回覆你目前已部署到哪個批次？ |

### 情境：使用者回「已部署到 B{n}」

**AI 回應格式**：

| 元素 | 內容 |
|---|---|
| 說明 | 需更新以下 {X} 檔（B{n} 之後所有批次，同檔以最新為準） |
| 列表 | 每行：`B{批次} ← 路徑` |
| 排序 | 依批次由舊到新，或依目錄 |

### 情境：使用者回「全未部署」

**AI 回應**：列全部批次的最新版清單。

## 六、常見錯誤操作修正

### 錯誤 1：只交付 diff

| 面向 | 說明 |
|---|---|
| 錯誤做法 | 給 diff 或部分內容 |
| 正確做法 | 交付完整檔案 |
| 理由 | AI 讀取需完整上下文 |

### 錯誤 2：用「...」「同上」

| 面向 | 說明 |
|---|---|
| 錯誤做法 | 中間省略，用「...」 |
| 正確做法 | 完整列出 |
| 理由 | 使用者複製貼上需完整 |

### 錯誤 3：多檔合併一個 code block

| 面向 | 說明 |
|---|---|
| 錯誤做法 | 一個 code block 含多個檔案 |
| 正確做法 | 每檔獨立區塊 |
| 理由 | 使用者需分開存檔 |

### 錯誤 4：含內層 code block 用 3 backtick

| 面向 | 說明 |
|---|---|
| 錯誤做法 | 外層用 3 backtick 但內容含 3 backtick |
| 正確做法 | 外層 = 內層最多 backtick + 1 |
| 理由 | 避免提前關閉 |

### 錯誤 5：用 code block 示範「含 code block 的格式」

| 面向 | 說明 |
|---|---|
| 錯誤做法 | 用 code block 示範含 code block 的東西 |
| 正確做法 | 用表格說明規則（見 0.18） |
| 理由 | 示範本身會造成嵌套 |

### 錯誤 6：忘記 END OF FILE 標記

| 面向 | 說明 |
|---|---|
| 錯誤做法 | 檔案末尾沒有標記 |
| 正確做法 | B20 起所有交付加標記 |
| 理由 | 檢查完整性與版本 |

### 錯誤 7：檔案 > 500 行

| 面向 | 說明 |
|---|---|
| 錯誤做法 | 單檔超過 500 行 |
| 正確做法 | 拆檔 |
| 理由 | 一次 text 可交付 |

## 七、檔案大小操作建議

| 類型 | 若超標 | 處理 |
|---|---|---|
| Page Schema | > 300 | 抽 customMount 邏輯至 lib |
| Block | > 300 | 抽共用邏輯至 lib |
| Lib | > 250 | 拆為多個 lib |
| Engine | > 500 | 拆引擎 |
| Functions API | > 800 | 拆 handler |

## 八、命名操作建議

| 類型 | 慣例 | 範例 |
|---|---|---|
| 檔案 | kebab-case | `expense-modal.js` |
| 類別 | PascalCase | `ExpenseModal` |
| 公開函式 | camelCase | `openExpenseModal` |
| 常數 | UPPER_SNAKE_CASE | `MAX_LEN` |
| 私有 / 內部 | `_leadingUnderscore` | `_render()` |
| CSS class | kebab-case | `view-toggle-group` |

**AI 優先例外**：內部區域變數可極簡（`_r`, `_m`, `_h`）。

## 九、多批交付操作

**若單次回應無法容納**：

| 步驟 | 動作 |
|---|---|
| 1 | 分批（每批 ≤ 3~4 檔，視大小） |
| 2 | 每批標「第 N/M 批」 |
| 3 | 使用者回「繼續」交付下一批 |
| 4 | 每批內容完整 |
| 5 | 含內層 code block 用 4 backtick |
| 6 | 每檔不跨回覆中斷 |

**檔數較多的情況**：

| 情況 | 每批檔數 |
|---|---|
| 檔案 < 200 行 | 每批 3~4 檔 |
| 檔案 200~400 行 | 每批 2 檔 |
| 檔案 > 400 行 | 每批 1 檔 |
