# 交付規則 — v103.0.18

最後更新：B19
適用版本：v103.0.18+

## 一、核心原則

1. 一次性最終版：同一檔案只交付一次
2. 依相依性排序：從底層 SSOT 到上層頁面
3. 每檔案獨立區塊：不可合併多檔
4. 不可 diff：必須完整檔案內容
5. 不可省略：禁止「...」「同上」「略」
6. 無補丁：能宣告就不手寫，能就地更新就不 destroy/create
7. 檔案大小：單檔 ≤ 500 行

## 二、交付格式

```
## 📁 檔案路徑

```
{相對路徑}
```

## 📄 檔案內容

```{lang}
（完整內容）
```
```

規則：

1. 檔案路徑單獨用一個 code block（無語言標示）
2. 檔案內容用 code block 包裹，附語言標示（js / md / json / css / html）
3. 若內容內含 ``` code block，外層用 4 backtick（````）包裹
4. 每個檔案獨立區塊，不可合併多檔
5. 內容必須完整
6. 不可用 diff
7. 不可用「...」「同上」「略」
8. 檔案最後加 END OF FILE 標記（B20 起）
9. 交付清單開頭必須標示「批次號」與「本輪第幾批」

## 三、檔案結束標記（B20 起強制）

每個交付檔案最後必須加：

```js
/* ═══════════════════════════════════════════
   END OF FILE
   File: {路徑}
   Version: {項目版本}
   Batch: {批次號}
   ═══════════════════════════════════════════ */
```

目的：
- 快速檢查是否為最新版
- 檢查檔案是否被截斷
- 便於工具掃描

## 四、交付批次號（強制）

格式：

| 範圍 | 格式 | 範例 |
|---|---|---|
| B01 ~ B99 | B + 2 位數字 | B01, ..., B99 |
| B99 之後 | C01 ~ C99 | C01, ..., C99 |
| C99 之後 | D01 ~ D99 | D01, ..., D99 |
| 依此類推 | 前綴字母 A → B → C → D → ... | |

重交付：`B{n}.{x}`（例：B18.1）

規則：
1. 每波交付必須有批次號
2. 檔案內註解：`v103.0.xx`（項目版本）+ 批次號
3. 禁止混用「波次」與「版本號」
4. 禁止每次換說法

## 五、更新清單流程

使用者說「需要更新清單」時：

1. AI 先列「所有已交付批次」
2. 使用者回「已部署到 B{n}」
3. AI 列「B{n} 之後所有批次的最新版清單」
4. 同檔以最新批次為準
5. 格式：`B{批次} ← 路徑`

## 六、禁止事項

- ❌ 只交付 diff
- ❌ 使用「...」「同上」「略」
- ❌ 合併多檔在同一 code block
- ❌ 省略任何段落
- ❌ 補丁式修改（加快取、猴子補丁）
- ❌ 重複「訂閱 → render → destroy → create」
- ❌ 檔案 > 500 行
- ❌ 未加 END OF FILE 標記（B20 起）

## 七、交付前自我檢查

- [ ] import 完整
- [ ] export 完整
- [ ] 無語法錯誤
- [ ] 符合 SSOT 原則
- [ ] 路徑與專案結構一致
- [ ] 所有 button 有 `type="button"`
- [ ] 狀態判定走 `status-registry`
- [ ] 名稱解析走 `entity-registry`
- [ ] 顯示文字走 `label-registry`
- [ ] 表格欄位走 `column-registry`
- [ ] 檔案最後有 END OF FILE 標記（B20 起）
- [ ] 已更新檔案清單

## 八、檔案大小建議

| 類型 | 建議行數 | 上限 |
|---|---|---|
| Registry | 50~150 | 300 |
| Engine | 200~300 | 500 |
| Block | 100~200 | 300 |
| Lib | 50~150 | 250 |
| UI 元件 | 100~250 | 400 |
| Layout | 100~200 | 300 |
| Page Schema | 30~150 | 300 |
| Functions API | 100~400 | 800 |
| Docs | 50~700 | 1000 |

## 九、命名慣例

- 檔案：`kebab-case.js`
- 類別：`PascalCase`
- 函式 / 變數：`camelCase`
- 常數：`UPPER_SNAKE_CASE`
- 私有：`_leadingUnderscore`
- CSS class：`kebab-case`

## 十、每波交付流程

1. 讀取 `progress.md` 確認當前波次
2. 讀取該波次檔案清單
3. 依相依性排序交付
4. 每檔交付後自我檢查
5. 本波完成後更新 `progress.md` + `anchor.md` 檔案清單
6. 回報摘要 + 下一步

## 十一、批次交付範例

本輪第 N 批：批次 B{nn}

| # | 檔案 | 版本 | 批次 |
|---|---|---|---|
| 1 | `js/xxx.js` | v103.0.xx | B{nn} |
| 2 | `js/yyy.js` | v103.0.xx | B{nn} |

## 十二、多批交付規則

若單次回應無法容納所有檔案：

1. 分批交付（每批 ≤ 3~4 檔，視檔案大小）
2. 每批標示「第 N 批」
3. 使用者回「繼續」交付下一批
4. 每批內容完整，不混用
5. 含內層 code block 者，外層必須用 4 backtick
6. 每份檔案不可跨回覆中斷
