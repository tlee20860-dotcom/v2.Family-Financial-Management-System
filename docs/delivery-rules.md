# 交付規則 — v103.0.0

## 一、核心原則

1. **一次性最終版**：同一檔案只交付一次
2. **依相依性排序**：從底層 SSOT 到上層頁面
3. **每檔案獨立區塊**：不可合併多檔
4. **不可 diff**：必須完整檔案內容
5. **不可省略**：禁止「...」「同上」「略」

## 二、交付格式

```markdown
## 📦 第 N 波：主題

### 📁 檔案路徑

```
js/config/xxx.js
```

### 📄 檔案內容

```js
// 完整內容
```

**✅ 第 X/Y 檔交付完成**

...

**本波摘要**：

| # | 檔案 | 變更 |
|---|---|---|
| 1 | ... | ... |

**下一步**：回覆「繼續」交付第 N+1 波
```

## 三、禁止事項

- ❌ 只交付 diff
- ❌ 使用「...」「同上」「略」
- ❌ 合併多檔在同一 code block
- ❌ 省略任何段落

## 四、交付前自我檢查

- [ ] import 完整
- [ ] export 完整
- [ ] 無語法錯誤
- [ ] 符合 SSOT 原則
- [ ] 路徑與專案結構一致
- [ ] 所有 button 有 `type="button"`
- [ ] 狀態判定走 `status-registry`
- [ ] 名稱解析走 `entity-registry`
- [ ] 顯示文字走 `label-registry`
- [ ] 表格欄位走 `column-registry`

## 五、檔案大小建議

| 類型 | 建議行數 | 上限 |
|---|---|---|
| Registry | 50~150 | 300 |
| Engine | 200~300 | 500 |
| Block | 100~200 | 300 |
| Lib | 50~150 | 250 |
| UI 元件 | 100~250 | 400 |
| Layout | 100~200 | 300 |
| Page Schema | 30~80 | 150 |
| Functions API | 100~400 | 800 |

## 六、命名慣例

- 檔案：`kebab-case.js`
- 類別：`PascalCase`
- 函式 / 變數：`camelCase`
- 常數：`UPPER_SNAKE_CASE`
- 私有：`_leadingUnderscore`
- CSS class：`kebab-case`

## 七、每波交付流程

1. 讀取 `progress.md` 確認當前波次
2. 讀取該波次檔案清單
3. 依相依性排序交付
4. 每檔交付後自我檢查
5. 本波完成後更新 `progress.md`
6. 回報摘要 + 下一步
